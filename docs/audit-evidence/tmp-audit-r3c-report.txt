THE STOPPING RULE
============================================================
The bar you proposed to Hymlock:

  An item is certified when an audit round finds no defect of a CLASS
  not already fixed. Variants inside an already-closed class get logged
  as known and accepted.

It is too low if YOU classify the leftover.

Today's item-15 fail is exactly what that sentence would let you call
a variant: adjacent, same class, not a repeat of the four gates you
just wrote. If adjacency is enough to accept it, we certify a class
that is still open.

A class is closed when the stated positive rule already DECIDES the
new attack — refuses it, or allows it as a written exception. A
VARIANT is a new spelling of something the rule already decides. A
HOLE is an attack the rule does not decide, or decides wrongly.

"tsc may see only the index and node_modules" decides today's attack
wrongly (bare extends is not walked; tsc saw the worktree). Not a
variant. The class is still open.

What I would use:

1. The rule is stated positively.
2. I classify each leftover, not you. You may argue; you may not decide.
3. VARIANT = the stated rule already refuses this, or already allows it
   as a named exception (hatch, noCheck-in-the-index).
4. HOLE = the stated rule does not decide this, or decides it wrongly.
5. Certify when a round produces no hole and no new class.
6. Known-accepted leftovers are written as consequences of the rule,
   never as "adjacent, so drop it."

That is a higher bar than "no new class." It is not an infinite bar.
Item 13 met it this round. Item 18 met it this round. Item 10's store
rule met it; the missing caller is a different class this bar already
names ("the store is not the feature") and it keeps the item open.
Item 15 did not.
